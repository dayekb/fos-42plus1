# Аннотации оценочных средств
**По занятию 1.1. Архитектура промпта и базовые паттерны** 
[Занятие 1.1]([https://github.com/dayekb/fos-42plus1/blob/main/M1-module-name/%D0%9C%D0%BE%D0%B4%D1%83%D0%BB%D1%8C%201.%20%D0%9A%D0%BE%D0%BD%D1%81%D0%BF%D0%B5%D0%BA%D1%82%20%D0%BB%D0%B5%D0%BA%D1%86%D0%B8%D0%B8.docx](https://github.com/dayekb/fos-42plus1/blob/main/M1-module-name/attachments/%D0%9A%D0%98%D0%9C%20%D0%97%D0%B0%D0%BD%D1%8F%D1%82%D0%B8%D0%B5%201.1.docx))
ОС №1. Тест с автопроверкой
Цель – проверить базовые знания о структуре промпта, параметрах API (temperature, top-p, max_tokens), техниках zero-shot, few-shot, Chain-of-Thought и Self-Consistency. Тест содержит 10 заданий с выбором ответа и установлением соответствия. Автоматическая проверка позволяет быстро оценить усвоение материала.

ОС №2. Мини-кейс (основной)
Цель – сформировать навык разработки промпта для реальной задачи классификации медицинских документов с извлечением сущностей. Студент создаёт промпт с системной ролью, инструкцией, few-shot-примером и структурированным JSON-выводом, обосновывает выбор техник и параметров API. Оценивается полнота структуры, обоснованность и качество извлечения.

ОС №3–7. Мини-кейсы для самостоятельной работы
Пять дополнительных кейсов от индустриальных партнёров позволяют закрепить навыки на разных доменах: проверка достоверности отзывов, маскировка ПДн, рекомендация курсов, подбор команд, классификация текстов. Каждый требует разработки промпта с обоснованием техник и параметров, что развивает гибкость мышления и умение адаптировать промпты под разные задачи.

**По занятию 1.2. Библиотеки промптов, версионирование, отладка и контроль**
[Занятие 1.2]([https://github.com/dayekb/fos-42plus1/blob/main/M1-module-name/%D0%9C%D0%BE%D0%B4%D1%83%D0%BB%D1%8C%201.%20%D0%9B%D0%B0%D0%B1%D0%BE%D1%80%D0%B0%D1%82%D0%BE%D1%80%D0%BD%D0%B0%D1%8F%20%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D0%B0.docx](https://github.com/dayekb/fos-42plus1/blob/main/M1-module-name/attachments/%D0%9A%D0%98%D0%9C%20%D0%97%D0%B0%D0%BD%D1%8F%D1%82%D0%B8%D0%B5%201.2.docx))
ОС №8. Тест с автопроверкой
Цель – оценить понимание принципов управления библиотекой промптов (Prompt Registry), семантического версионирования, CI/CD-пайплайнов для промптов, методов отладки (Logit Lens, анализ внимания) и стратегий выравнивания / контроля галлюцинаций. Вопросы охватывают ключевые понятия PromptOps.

ОС №9. Лабораторная работа
Цель – дать практический опыт создания централизованной библиотеки промптов с версионированием и CI/CD-пайплайном. Студенты разрабатывают структуру хранения (YAML/JSON), загрузчик промптов, модульные тесты (pytest) и настраивают автоматический запуск проверок при PR/merge. Работа выполняется в команде, что развивает навыки коллективной разработки. Результат – готовый репозиторий с документацией и отчётом.

**По занятию 1.3. Сложные сценарии и мультимодальность**

ОС №10. Практическое задание (на паре)
Цель – освоить проектирование цепочки мультимодальных промптов с условной логикой на примере обработки медицинских документов. Студенты разрабатывают четыре последовательных промпта (классификация, извлечение текста, извлечение сущностей, валидация) и объединяют их в пайплайн. Оценивается умение использовать мультимодальный вход (изображение), условные переходы и формировать структурированный JSON с метрикой уверенности.

ОС №11–15. Задания для самостоятельной работы
Пять заданий углубляют навыки работы со сложными сценариями: условная логика для маскировки ПДн, цепи промптов для унификации расписания, мультимодальный анализ отзывов, безопасная передача документов и нормализация изображений. Каждое задание требует продуманной архитектуры промптов и обоснования, что готовит студентов к финальной защите модуля.

**По занятию 1.4. Ревью практической работы модуля 1**
[Занятие 1.4](https://github.com/dayekb/fos-42plus1/blob/main/M1-module-name/%D0%9C%D0%BE%D0%B4%D1%83%D0%BB%D1%8C%201.%20%D0%9F%D1%80%D0%BE%D0%B5%D0%BA%D1%82.docx)
ОС №16. Защита ЛР / Код-ревью
Цель – комплексная проверка всех компетенций модуля 1. Студенты защищают разработанную библиотеку промптов и условный пайплайн для управления функциями ИИ-агента (Feature Flags). Защита включает презентацию архитектуры, демонстрацию работы пайплайна (с обработкой ошибок и fallback), код-ревью (качество, тесты, CI/CD) и ответы на вопросы по безопасности, версионированию и мониторингу. Оценивается системность подхода и глубина понимания.

ОС №17–21. Задания для самостоятельной работы (подготовка к защите)
Пять заданий позволяют детально проработать отдельные аспекты модуля: разработка библиотеки для медицинских документов (№17), условный пайплайн для расписания (№18), мультимодальная проверка отзывов (№19), настройка CI/CD (№20) и комплексная подготовка защиты (№21). Они обеспечивают всестороннюю подготовку и дают возможность получить дополнительные баллы за углублённую проработку тем.
