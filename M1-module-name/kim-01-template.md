# КИМ-1.1. [Модуль 1: Prompt Engineering]

📌 ##  Занятие 1.1. Архитектура промпта и базовые паттерны  
КИМ №1. Тест с автопроверкой «Архитектура промпта и базовые паттерны»  
Тест предназначен для первичной проверки усвоения базового материала занятия. Студенту предлагается ответить на 10 вопросов в течение 20 минут. Формат заданий разнообразный: выбор одного правильного ответа, выбор нескольких правильных ответов, установление соответствий между элементами.
Вопросы охватывают ключевые темы занятия: параметры генерации (temperature, top-p, top-k, max_tokens), базовые паттерны промптинга (zero-shot, few-shot), продвинутые техники рассуждения (Chain-of-Thought, Self-Consistency), а также архитектуру качественного промпта (роль, инструкция, контекст, ограничения, формат вывода).
Оценивание: 1 правильный ответ = 1 балл. Порог «зачтено» — 8–10 баллов, «не зачтено» — 0–7 баллов. Компетенция: LLM-5 (индикаторы 5.1, 5.2, 5.3).  
КИМ №2. Мини-кейс «Разработка промпта для классификации медицинских документов»  
Основное практическое задание занятия, выполняемое в аудитории за 40 минут. Студенту предлагается реальная задача от индустриального партнёра ООО «МедРокет»: разработать промпт для классификации медицинских документов (заключение, рецепт, анализы, направление, план лечения) с извлечением структурированных сущностей в JSON-формат.
Результатом работы является не только сам промпт, но и пояснительная записка с обоснованием выбора техник промптинга (role prompting, few-shot, структурированный вывод) и параметров API (temperature, top-p, max_tokens). Оценивается полнота архитектуры промпта, корректность использования техник, глубина обоснования, настройка параметров и качество извлечения сущностей. Максимум — 10 баллов.  
КИМ №3–7. Мини-кейсы для самостоятельной работы  
Пять дополнительных мини-кейсов, которые студент выполняет самостоятельно для закрепления материала. Каждый кейс основан на реальной задаче от индустриальных партнёров (ООО «МедРокет», ООО «ГК Иннотех») и требует разработки промпта с обоснованием выбора техник и параметров API.  
Мини-кейс №1 — проверка отзывов о врачах на достоверность (анализ риска, копипасты, шаблонности).  
Мини-кейс №2 — маскировка персональных данных в тексте с частичным скрытием дат.  
Мини-кейс №3 — рекомендация онлайн-курсов по описанию пользователя.  
Мини-кейс №4 — подбор участников в команду по компетенциям.  
Мини-кейс №5 — классификация темы текста, извлечение ключевых слов, оценка тональности.  
Для каждого кейса студент должен представить итоговый промпт, обоснование выбора техник, рекомендуемые параметры API и пример работы на тестовых данных.  
📌 ## Занятие 1.2. Библиотеки промптов и версионирование
КИМ №8. Тест с автопроверкой «Библиотеки промптов, версионирование и CI/CD»
Второй контрольный тест модуля, проверяющий понимание концепции PromptOps. 10 вопросов выполняются за 20 минут. Темы: Prompt Registry как единый источник истины, семантическое версионирование (SemVer), этапы CI/CD-пайплайна для промптов, методы отладки (Logit Lens, Attention Lens, активационный паддинг), стратегии контроля галлюцинаций (RAG, self-verification, детекция по скрытым состояниям), выравнивание (alignment).
Порог «зачтено» — 8–10 баллов. Компетенция: LLM-5 (индикаторы 5.5, 5.6, 5.8).
КИМ №9. Лабораторная работа «Разработка библиотеки промптов с CI/CD-пайплайном»
Ключевая практическая работа модуля, выполняемая в группах до 4 человек с распределением ролей (Team Lead, Developer, QA, DevOps). Трудоёмкость: 2 часа аудиторной работы плюс самостоятельная доработка в течение недели.
Кейс основан на задаче от ООО «ГК Иннотех»: команда разрабатывает платформу для поиска IT-специалистов в проектные команды и сталкивается с проблемой отсутствия версионирования промптов.
Часть А (40% оценки) — разработка библиотеки промптов:
Создание структуры с отдельными поддиректориями для каждого сценария
Оформление YAML/JSON-файлов с обязательными полями (id, version, description, model, parameters, system, template, changelog)
Реализация минимум трёх промптов: поиск кандидатов, рекомендация проектов, модерация описаний
Написание загрузчика на Python с поддержкой версий и подстановкой переменных
Настройка Git-версионирования с симлинком latest
Часть Б (30% оценки) — настройка CI/CD-пайплайна:
Подготовка тестовых наборов (≥5 примеров на промпт)
Написание модульных тестов на pytest с инкрементальным тестированием
Настройка GitHub Actions/GitLab CI с автоматической валидацией, тестированием и деплоем в staging
Часть В (30% оценки) — документация и демонстрация:
Подготовка README.md с описанием архитектуры
Демонстрация работы системы на одном из сценариев
Отчёт со структурой библиотеки, примерами промптов, скриншотами логов CI/CD, результатами тестирования
Максимум — 100 баллов. Шкала: 80–100 — отлично, 60–79 — хорошо, 40–59 — удовлетворительно, 0–39 — неудовлетворительно.
📌 ## Занятие 1.3. Сложные сценарии и мультимодальность
КИМ №10. Практическое задание в парах «Мультимодальный пайплайн для обработки медицинских документов»
Основное аудиторное задание, выполняемое в парах за 2 часа. Кейс от ООО «МедРокет»: студенты разрабатывают цепь мультимодальных промптов для мобильного приложения с электронной медицинской книжкой.
Цепочка состоит из четырёх промптов:
Классификация документа — определение типа по изображению
Извлечение текста — распознавание с учётом ошибок OCR и медицинской терминологии
Извлечение сущностей — выделение ключевых данных с условной логикой (если рецепт → препараты, если заключение → диагнозы)
Валидация и оценка уверенности — формирование предупреждения о необходимости ручной проверки
Требования: использование условной логики, мультимодального подхода (вход — изображение, выход — JSON), техники Chain-of-Thought, обработка низкого качества изображения. Оценивается корректность архитектуры, условная логика, обработка ошибок, мультимодальность, структура выхода, оптимизация, документация и тестирование. Максимум — 20 баллов.
КИМ №11–15. Задания для самостоятельной работы
Пять самостоятельных заданий, развивающих навыки проектирования сложных промптов и мультимодальных пайплайнов.
Задание 11 — «Детектив данных»: условные промпты для маскировки ПДн (ФИО, документы, контакты) с проверкой уверенности распознавания.
Задание 12 — «Универсальный переводчик»: цепь промптов для унификации расписания из разных форматов (JSON, XML, CSV, YAML) с детектором формата, парсером, нормализатором, матчером и валидатором.
Задание 13 — «Фейк-контроль»: мультимодальный промпт для проверки достоверности отзывов (анализ текста, профиля пользователя, метаданных, изображений) с оценкой риска и рекомендацией.
Задание 14 — «Сейф-доктор»: цепь промптов для безопасной передачи медицинских документов с классификацией чувствительности, определением срока доступа и логированием.
Задание 15 — «Фото-доктор»: мультимодальный промпт для анализа качества изображений документов и формирования инструкций по коррекции.
📌 З## анятие 1.4. Ревью практической работы модуля 1
КИМ №16. Защита лабораторной работы / Код-ревью
Финальное оценочное средство модуля, проводимое в форме защиты перед экспертной комиссией (2 часа). Кейс от ООО «Спортмастер Лаб»: студент защищает разработанную им библиотеку промптов и условный пайплайн с Feature Flags для управления функциями ИИ-агента.
Защита состоит из четырёх этапов:
Презентация библиотеки промптов (15 мин) — демонстрация структуры, версионирования, метаданных, 5+ промптов разных типов (системные, пользовательские, условные, мультимодальные, оценочные), обоснование архитектурных решений.
Демонстрация условного пайплайна (15 мин) — live-демо работы с Feature Flags, обработка ошибок, fallback-сценарии, логирование и трассировка решений.
Код-ревью (15 мин) — качество кода, модульность, автоматические тесты (≥5 тест-кейсов), CI/CD-пайплайн.
Ответы на вопросы комиссии (15 мин) — вопросы по архитектуре, безопасности (защита от промпт-инъекций), качеству, производительности, борьбе с галлюцинациями.
Максимум — 100 баллов. Шкала: 90–100 — отлично, 75–89 — хорошо, 60–74 — удовлетворительно, <60 — неудовлетворительно. Компетенция: LLM-5 (все индикаторы 5.1–5.8).
КИМ №17–21. Задания для самостоятельной работы (подготовка к защите)
Пять заданий, которые студент выполняет для подготовки к финальной защите. Каждое задание развивает определённый аспект компетенций модуля.
Задание 17 — разработка библиотеки промптов для обработки медицинских документов (5 промптов: классификация, извлечение, маскировка, оценка уверенности, суммаризация) с версионированием, документацией и тестами.
Задание 18 — реализация условного пайплайна для унификации расписания с обработкой 3+ форматов, fallback-промптом, логированием и минимум 3 тестами.
Задание 19 — мультимодальный пайплайн для проверки достоверности отзывов с цепочкой промптов, оценкой риска, сравнением и тестированием на 10+ примерах.
Задание 20 — настройка CI/CD-пайплайна для библиотеки промптов с автоматическими проверками, канареечным развертыванием и A/B-сравнением.
Задание 21 — комплексная подготовка к защите модуля 1: презентация архитектуры, демонстрация работы пайплайна, ответы на вопросы по безопасности, версионированию, качеству и галлюцинациям.
📊 # Общая структура КИМ модуля 1
Модуль включает 21 оценочное средство, распределённых по четырём занятиям:
Занятие 1.1 (7 КИМ): тест с автопроверкой + основной мини-кейс + 5 мини-кейсов для самостоятельной работы. Фокус на базовых паттернах промптинга и настройке API.
Занятие 1.2 (2 КИМ): тест с автопроверкой + лабораторная работа. Фокус на системном управлении промптами, версионировании и CI/CD.
Занятие 1.3 (6 КИМ): практическое задание в парах + 5 самостоятельных заданий. Фокус на сложных сценариях и мультимодальности.
Занятие 1.4 (6 КИМ): защита лабораторной работы + 5 самостоятельных заданий. Фокус на комплексной защите и код-ревью.
Все КИМ ориентированы на формирование компетенции LLM-5 (Проектирование промптов) и покрывают все 8 индикаторов: от базовой структуры промпта (5.1) до создания библиотеки промптов (5.8).
