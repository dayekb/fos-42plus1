# 📚 Шпаргалка преподавателя (Cheat Sheet)

Краткие справочные материалы для быстрых ответов на семинарах и код-ревью.

## 1. Параметры генерации: когда и что менять?

| Параметр | Что делает | Когда увеличивать | Когда уменьшать |
| :--- | :--- | :--- | :--- |
| **Temperature** | Контролирует случайность выбора следующего слова. | Творческие задачи: мозговой штурм, написание стихов, генерация идей (0.7 – 1.2). | Фактологические задачи: извлечение данных, код, саммари, RAG (0.0 – 0.3). |
| **Top_P** (Nucleus) | Отсекает "хвост" распределения вероятностей, оставляя только слова с кумулятивной вероятностью P. | Когда нужно больше разнообразия, но с контролем над полным хаосом (0.8 – 0.95). | Когда нужна строгая предсказуемость (0.1 – 0.5). *Обычно не используется одновременно с низкой температурой.* |
| **Frequency Penalty** | Штрафует слова, которые уже часто встречались в ответе. | Когда модель зацикливается и повторяет одни и те же фразы. | Почти никогда (может сделать текст неестественным). |
| **Presence Penalty** | Штрафует слова, которые уже встречались в ответе (даже 1 раз). | Когда нужно, чтобы модель перешла к новым темам или идеям. | При строгих форматах вывода (например, JSON), где ключи должны повторяться. |
| **Seed** | Фиксирует генератор случайных чисел. | Для отладки: чтобы при одном и том же промпте получать идентичный ответ для проверки изменений. | В продакшене, где нужно разнообразие ответов. |

> 💡 **Золотое правило:** Никогда не меняйте `Temperature` и `Top_P` одновременно при отладке. Меняйте один параметр за раз, чтобы понимать его влияние.

## 2. Уровни зрелости RAG-систем (для оценки архитектуры)

1. **Naive RAG (Базовый):** 
   - *Схема:* Запрос → Embedding → Поиск по схожести → Склейка с промптом → LLM.
   - *Проблемы:* Теряет контекст при больших документах, чувствителен к формулировке запроса.
2. **Advanced RAG (Продвинутый):** 
   - *Добавки:* Переформулирование запроса (Query Rewriting), гибридный поиск (keyword + vector), reranking (переранжирование топ-50 документов более тяжелой моделью перед подачей в LLM).
3. **Agentic RAG (Агентный):** 
   - *Схема:* LLM выступает как роутер. Она сама решает: "Мне нужно поискать в базе?", "Нужно ли уточнить запрос у пользователя?", "Достаточно ли информации для ответа?". Использует цикл рассуждений (ReAct).

## 3. Квантование GGUF: что означают суффиксы?

| Суффикс | Точность | Размер (для 7B модели) | Качество | Рекомендация |
| :--- | :--- | :--- | :--- | :--- |
| `Q2_K` | ~2 бита | ~2.5 ГБ | Низкое, заметные потери | Только для очень слабого железа. |
| `Q4_K_M` | ~4 бита | ~4.5 ГБ | **Оптимальное** (почти как оригинал) | **Рекомендуется по умолчанию** для 90% задач. |
| `Q5_K_M` | ~5 бит | ~5.5 ГБ | Очень высокое | Если есть запас памяти и нужна максимальная точность. |
| `Q8_0` | ~8 бит | ~7.5 ГБ | Практически неотличимо от fp16 | Для мощных ПК, когда качество критично. |
| `FP16` | 16 бит | ~14 ГБ | Эталонное | Редко имеет смысл для локального инференса. |
