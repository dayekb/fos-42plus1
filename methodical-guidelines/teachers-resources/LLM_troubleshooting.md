# 🛠️ Руководство по решению технических проблем (Troubleshooting)

Этот документ содержит решения наиболее частых ошибок, с которыми сталкиваются студенты при работе с локальными LLM (Ollama) и облачными API (GigaChat).

## 1. Проблемы с локальным запуском (Ollama)

### ❌ Ошибка: `Out of Memory` (OOM) или зависание компьютера
**Симптом:** При выполнении `ollama run` компьютер начинает сильно тормозить, или в терминале появляется ошибка нехватки памяти.
**Решение:**
1. Уменьшить контекстное окно: добавить параметр `--num_ctx 2048` (или меньше).
2. Использовать более легкую модель: вместо `llama3:8b` запустить `llama3.2:3b` или `qwen2.5:3b`.
3. Использовать более сильное квантование: выбрать тег `q4_k_m` вместо `q8_0` или `fp16`.
4. Закрыть тяжелые приложения (браузер с десятками вкладок, IDE).

### ❌ Ошибка: `Connection refused` при обращении к `localhost:11434`
**Симптом:** Скрипт на Python или curl не может подключиться к Ollama.
**Решение:**
1. Убедиться, что приложение Ollama запущено (должен быть значок в трее на Windows/macOS или активный процесс `ollama serve` на Linux).
2. Проверить порт: выполнить в терминале `curl http://localhost:11434/api/tags`. Если возвращает список моделей, значит сервер работает, и проблема в коде студента (опечатка в URL).
3. На Windows: иногда антивирус блокирует локальные порты. Добавить `ollama.exe` в исключения.

### ❌ Ошибка: Генерация идет экстремально медленно (1-2 токена в секунду)
**Симптом:** Модель работает, но ответ печатается очень долго.
**Решение:** Объяснить студенту, что модель выполняется на CPU, а не на GPU. Для ускорения необходимо:
- На macOS: убедиться, что используется Apple Silicon (Ollama автоматически использует Metal).
- На Windows/Linux с NVIDIA: установить CUDA-драйверы и убедиться, что Ollama видит GPU (команда `nvidia-smi` должна показывать видеокарту).

## 2. Проблемы с облачным API (GigaChat)

### ❌ Ошибка: `401 Unauthorized`
**Симптом:** API возвращает ошибку авторизации.
**Решение:**
1. Проверить срок жизни `Access Token`. Он действует ровно 30 минут. Если скрипт работает дольше, нужно добавить логику обновления токена.
2. Убедиться, что `Authorization Key` сформирован верно: `base64(Client_ID:Client_Secret)`. Двоеточие между ID и Secret обязательно!
3. Проверить, что в запросе токена указан корректный `scope`: `GIGACHAT_API_PERS` (для физлиц).

### ❌ Ошибка: `429 Too Many Requests`
**Симптом:** Превышен лимит запросов.
**Решение:**
1. Напомнить о лимитах бесплатного (Freemium) тарифа GigaChat (например, N запросов в минуту).
2. Добавить в код простейший механизм **Exponential Backoff** (повторная попытка запроса с задержкой 2с, 4с, 8с при получении ошибки 429).

### ❌ Ошибка: `SSL Certificate Verify Failed` (Python)
**Симптом:** Библиотека `requests` или SDK падает с ошибкой сертификата.
**Решение:** Обновить корневые сертификаты в системе или (временно, для учебных целей) добавить `verify=False` в запрос `requests`, предупредив о рисках безопасности.

## 3. Проблемы с кодом и логикой

### ❌ Модель выдает ответ в формате Markdown, а нужен строгий JSON
**Решение:** 
1. Явно указать в системном промпте: "Отвечай ТОЛЬКО валидным JSON-объектом, без пояснений и markdown-обёрток (```json)".
2. Использовать параметр `stop: ["```"]` в Ollama или аналогичный в API.
3. В коде Python использовать библиотеку `pydantic` или `json_repair` для исправления мелких синтаксических ошибок в ответе LLM.

### ❌ RAG-система "галлюцинирует" или игнорирует контекст
**Решение:**
1. Проверить промпт: инструкция "Ответь, используя ТОЛЬКО предоставленный контекст" должна быть в начале или конце промпта.
2. Уменьшить `temperature` до `0.1` или `0.0` для задач извлечения фактов.
3. Проверить, что `top_k` и `num_ctx` не обрезывают переданный контекст.
