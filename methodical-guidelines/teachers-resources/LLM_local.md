# Локальный запуск больших языковых моделей (на примере Ollama)

> **Ключевые слова:** `Local LLM`, `Ollama`, `GGUF`, `Quantization` (квантование), `llama.cpp`, `Privacy`, `Local API`, `Open-source models`, `Llama 3`, `Mistral`, `Num_ctx`.

## 1. Что такое локальный запуск LLM и зачем он нужен?

**Локальный инференс (Local Inference)** — это процесс запуска и выполнения больших языковых моделей непосредственно на оборудовании пользователя (локальный ПК, сервер или edge-устройство), без отправки данных во внешние облачные сервисы.

Ключевые преимущества локального запуска:
- **Конфиденциальность и безопасность данных**: Информация (включая персональные или корпоративные данные) никогда не покидает периметр вашей сети.
- **Отсутствие зависимости от интернета**: Модели работают полностью офлайн.
- **Нулевая стоимость инференса**: Нет платы за токены или подписки, только амортизация оборудования.
- **Полный контроль**: Возможность тонкой настройки параметров, модификации системных промптов и интеграции с локальными базами данных (RAG) без ограничений провайдеров.

## 2. Ollama: стандарт де-факто для локальных LLM

**Ollama** — это кроссплатформенный инструмент с открытым исходным кодом, который радикально упрощает запуск, управление и взаимодействие с открытыми языковыми моделями на macOS, Linux и Windows. 

Под капотом Ollama использует оптимизированный движок **`llama.cpp`**, который позволяет эффективно задействовать как CPU, так и GPU (через Metal на macOS или CUDA на NVIDIA) для выполнения моделей, сжатых с помощью **квантования** (формат `GGUF`).

> ⚠️ **Требование курса:** Для выполнения практических заданий модуля необходимо установить Ollama и загрузить как минимум одну открытую модель (например, `llama3`, `qwen2.5` или `mistral`) с размером квантования, подходящим под объем оперативной памяти вашего устройства.

## 3. Базовый рабочий процесс в CLI

Взаимодействие с Ollama начинается с командной строки (терминала). Основные команды управления моделями:

| Команда | Описание |
| :--- | :--- |
| `ollama run <имя_модели>` | Загружает модель (если её нет) и запускает интерактивный чат в терминале. Пример: `ollama run llama3.2` |
| `ollama pull <имя_модели>` | Только загружает или обновляет модель в локальном кэше без запуска чата. |
| `ollama list` | Показывает список всех загруженных локально моделей и их размеры. |
| `ollama rm <имя_модели>` | Удаляет модель с диска для освобождения места. |
| `ollama ps` | Показывает модели, которые в данный момент загружены в оперативную память и готовы к работе. |

*Популярные модели для локального запуска:* `llama3.2` (1B/3B), `qwen2.5` (7B/14B), `mistral` (7B), `gemma2` (9B), `deepseek-coder` (6.7B).

## 4. Взаимодействие через локальный REST API

Одно из главных преимуществ Ollama — он автоматически разворачивает локальный веб-сервер, предоставляющий API, совместимый по логике с облачными решениями (например, OpenAI). 

По умолчанию сервер доступен по адресу: `http://localhost:11434`

### Пример запроса через `curl` (эндпоинт `/api/chat`)

```bash
curl http://localhost:11434/api/chat -d '{
  "model": "llama3.2",
  "messages": [
    { "role": "system", "content": "Ты полезный ассистент, отвечающий кратко." },
    { "role": "user", "content": "Объясни, что такое квантование в двух предложениях." }
  ],
  "stream": false,
  "options": {
    "temperature": 0.7,
    "num_ctx": 4096
  }
}'
```

> 💡 **Примечание для разработчиков:** Благодаря совместимости, популярные библиотеки (LangChain, LlamaIndex, OpenAI Python SDK) легко перенастраиваются на работу с локальным `base_url="http://localhost:11434/v1"`, что позволяет бесшовно переключаться между облачными и локальными моделями в коде.

## 5. Ключевые параметры генерации в Ollama

Параметры передаются внутри объекта `options` в JSON-запросе. Они аналогичны облачным API, но имеют локальную специфику.

| Параметр | Описание и влияние на генерацию |
| :--- | :--- |
| `model` | Имя локально загруженной модели (например, `"qwen2.5:7b"`). |
| `messages` | Массив сообщений диалога (`system`, `user`, `assistant`). |
| `temperature` | Управляет креативностью (аналогично облачным API). |
| `top_p` / `top_k` | Параметры выборки (nucleus sampling), ограничивающие пул кандидатов на следующее слово. |
| `num_ctx` | **Критически важный параметр для локальных LLM.** Размер контекстного окна в токенах (по умолчанию часто 2048 или 4096). Увеличение требует больше оперативной памяти (VRAM/RAM). |
| `num_predict` | Максимальное количество токенов, которое модель сгенерирует в ответе (аналог `max_tokens`). `-1` означает генерацию до естественного конца. |
| `stop` | Массив строк, при встрече которых генерация будет немедленно остановлена (полезно для форматированного вывода, например, JSON). |
| `seed` | Фиксированное число для воспроизводимости результатов (при одинаковом промпте и seed модель выдаст идентичный ответ). |

## 6. Аппаратные требования и оптимизация (GGUF и Квантование)

Локальный запуск стал возможен благодаря **квантованию** — процессу снижения точности весов модели (например, с 16-битных чисел с плавающей запятой до 4-битных целых чисел) с минимальной потерей качества.

- **Формат GGUF**: Современный стандарт хранения квантованных моделей, оптимизированный для быстрого чтения с диска и эффективного использования CPU/GPU.
- **Маркировка моделей**: В реестре Ollama модели часто имеют суффиксы, указывающие на степень сжатия:
  - `q4_k_m` (4-битное квантование): Оптимальный баланс качества и скорости. Требует ~5-6 ГБ ОЗУ для 7B-модели.
  - `q8_0` (8-битное квантование): Почти не отличимо от оригинала по качеству, но требует в 2 раза больше памяти.
  - `fp16`: Полная точность (редко используется локально из-за огромных требований к памяти).

> **Правило большого пальца:** Для комфортной работы 7-миллиардной (7B) модели с квантованием Q4 требуется минимум 8 ГБ объединенной оперативной памяти (RAM + VRAM).
