## 💡 Ключевые разделы для быстрого доступа

### 🚩 Типичные ошибки студентов (Чек-лист для проверки)
При проверке работ или во время защиты обращайте особое внимание на следующие антипаттерны:

| Ошибка | На что обратить внимание при проверке |
|---|---|
| **Отсутствие версионирования** | Промпты без поля `version`, нет истории изменений (`changelog`), невозможно откатить версию. |
| **Монолитная структура** | Все промпты свалены в один файл вместо модульной структуры по типам задач. |
| **Нет обработки ошибок** | Пайплайн падает при первой же ошибке API (отсутствуют `try-catch`, `retry` или `fallback`). |
| **Отсутствие тестов** | Код или промпты не покрыты автоматическими (`pytest`) или ручными тест-кейсами. |
| **Игнорирование безопасности** | Нет защиты от промпт-инъекций, экранирования или маскировки PII-данных. |
| **Плохая презентация** | Нечитаемые слайды (шрифт < 24pt), отсутствие структуры, превышение тайминга (5–7 мин). |

### 📋 Чек-лист подготовки преподавателя к защите (Модуль 1)
- [ ] Утвержден список студентов, допущенных к защите (предзащита за 3 дня).
- [ ] Сформирована комиссия (2–3 человека) и розданы бланки оценки с дескрипторами.
- [ ] Проверен доступ к API LLM (лимиты, ключи) и подготовлено резервное offline-демо.
- [ ] Студентам разослан регламент защиты за 1 неделю, проведена консультация.
- [ ] Подготовлен банк вопросов и примеры эталонных решений для сверки.
