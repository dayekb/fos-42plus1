# 🎓 Методические указания для преподавателей и экспертов по оцениванию

Добро пожаловать в раздел методических материалов для преподавателей и членов экзаменационной комиссии дисциплины **«Инженерия систем на базе больших языковых моделей»**. 

Здесь собраны критерии оценивания, эталонные ответы, тайминги занятий и банк вопросов для проведения объективной, структурированной и справедливой оценки знаний студентов.

---

## 🗂️ Навигация по материалам

### 1️⃣ Критерии оценивания и эталонные ответы (КИМ)
Материалы для объективной проверки практических работ и мини-кейсов.
- 📊 [**Рубрика и эталонный ответ для КИМ 1.02**](./assessment_rubric_1.02.md)  
  *Детальные критерии оценивания (шкала 0–10 баллов), эталонный промпт для классификации медицинских документов и обоснование выбора техник для проверяющего.*

### 2️⃣ Модуль 1: Prompt Engineering (Промпт-инженерия)
Пошаговые инструкции по организации учебного процесса, таймингу и работе с типичными ошибками.
- 📚 [**Гайд преподавателя: Занятие 1.03 (Сложные сценарии и мультимодальность)**](./instructor_guide_1.03.md)  
  *Подготовка материалов, жесткий тайминг (10+15+45+10+20 мин), разбор типичных ошибок студентов при построении цепочек промптов.*
- 🛡️ [**Гайд преподавателя: Занятие 1.04 (Ревью и защита модуля)**](./instructor_guide_1.04_defense.md)  
  *Полный цикл организации защиты: формирование комиссии, техническая подготовка, регламент, банк из 30 вопросов для экзаменаторов и пост-анализ результатов.*


### 3️⃣ Модуль 2: Context Engineering (Оценивание и методическая поддержка)
Инструменты для проверки лабораторных работ, анализа метрик автопроверки и проведения защиты индивидуальных проектов.

- 📊 [**Рубрика и эталонные ответы для Лабораторной работы 2.2**](/methodical-guidelines/teachers-assessment/assessment_rubric_2.02.md)  
  *Критерии оценки базового RAG-пайплайна: чанкинг, выбор БД, цитирование, порог Recall@k ≥ 0.60.*
- ⚙️ [**Методика проверки Лабораторной работы 2.3 (с автопроверкой)**](/methodical-guidelines/teachers-assessment/assessment_guide_2.03.md)  
  *Как интерпретировать результаты скрипта `auto_check.py` (порог: +15% улучшения или абсолютный Recall@5 ≥ 0.85). Типичные ошибки при реализации RRF и Cross-encoder.*
- 🛡️ [**Регламент и рубрика защиты Индивидуального проекта 2.4**](/methodical-guidelines/teachers-assessment/assessment_rubric_2.4_defense.md)  
  *Полный гайд для комиссии: хронометраж защиты, структура из 10 обязательных слайдов, таблица 20 вариантов заданий, банк типовых вопросов по метрикам и компромиссам (latency vs качество).*
- 🧠 [**Сводные методические рекомендации по Модулю 2**](./module_2_methodology_common.md)  
  *Чек-лист типичных ошибок студентов (с указанием, в какой работе они встречаются), нюансы оценивания и советы по организации защиты.*
