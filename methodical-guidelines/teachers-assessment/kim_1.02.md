#### ОС №2: Мини-кейс «Классификация медицинских документов»

| Параметр | Значение |
|---|---|
| Наименование | Мини-кейс «Разработка промпта для классификации медицинских документов» |
| Вид КИМ | Мини-кейс (практическое задание) |
| Компетенции | LLM-5 (5.1, 5.2, 5.3), PL-1.1 |
| Уровень | Базовый |
| Время | 40 минут |
| Источник кейса | ООО «МедРокет» (Кейс 1) |

**Контекст:** В мобильном приложении с электронной медицинской книжкой пациенты загружают фото медицинских документов. Врачу нужно быстро находить информацию, пациенту — отслеживать назначения.

**Задача:** Разработать промпт, который:
1. Определяет тип документа (заключение, рецепт, анализы, направление, план лечения).
2. Извлекает сущности: ФИО, дата, врач/клиника, диагнозы, препараты, дата повторного приёма.
3. Возвращает результат в JSON.
4. Содержит обоснование выбора техник и параметров API.

**Критерии оценивания (Rubric):**

| Критерий | 0–2 | 3–4 | 5 |
|---|---|---|---|
| Структура промпта | Отсутствует | Основные элементы | Полная архитектура |
| Использование техник | Не используются | 1 техника | 2+ техники |
| Обоснование выбора | Отсутствует | Поверхностное | Глубокое |
| Настройка API | Не указаны | Без обоснования | С обоснованием |
| Качество извлечения | Не все сущности | Все, но неструктурированно | Все + JSON-схема |

**Итого:** 0–10 баллов.

**Эталонный ответ (для преподавателя):**

````markdown
Ты — эксперт по обработке и классификации медицинских документов.
Твоя задача — определить тип медицинского документа по его тексту и извлечь ключевые структурированные данные.

Типы документов:
1. Заключение врача — содержит диагноз, рекомендации, результаты осмотра
2. Рецепт — содержит назначенные препараты, дозировки, способ применения
3. Результаты анализов — содержит числовые показатели, референсные значения
4. Направление — содержит ФИО пациента, диагноз, направление к специалисту
5. План лечения — содержит этапы лечения, даты, процедуры

Инструкция:
1. Проанализируй текст документа.
2. Определи его тип из списка выше.
3. Извлеки следующие сущности (если они присутствуют):
   - patient_name: ФИО пациента
   - document_date: дата документа (ГГГГ-ММ-ДД)
   - doctor: ФИО врача
   - clinic: название клиники
   - diagnoses: список диагнозов
   - medications: список препаратов с дозировками
   - next_appointment: дата следующего приёма

Пример (few-shot):
Текст: "Пациент Иванов Иван Иванович, 45 лет. Заключение терапевта от 15.03.2025. Диагноз: гипертоническая болезнь II стадии. Рекомендовано: приём эналаприла 10 мг 2 раза в день. Повторный приём через 2 недели."
Результат:
```json
{
  "document_type": "Заключение врача",
  "patient_name": "Иванов Иван Иванович",
  "document_date": "2025-03-15",
  "doctor": "терапевт",
  "clinic": null,
  "diagnoses": ["гипертоническая болезнь II стадии"],
  "medications": ["эналаприл 10 мг 2 раза в день"],
  "next_appointment": "2025-03-29"
}

Теперь обработай следующий документ:
[ТЕКСТ ДОКУМЕНТА]
````

**Обоснование:**

| Элемент | Обоснование |
|---|---|
| Role prompting | Повышает точность и релевантность |
| Few-shot (1 пример) | Демонстрирует ожидаемый формат JSON |
| Структурированный вывод | Обеспечивает автоматическую обработку |
| Чёткая спецификация сущностей | Уменьшает пропуски |
| `temperature = 0.1` | Детерминированный, воспроизводимый результат |
| `max_tokens = 500` | Достаточно для JSON, ограничивает избыточность |
