#### Задание 1. Разработка библиотеки промптов для обработки медицинских документов

**Источник кейса:** ООО «МедРокет»

**Постановка задачи:** Разработайте библиотеку промптов для мультимодальной обработки медицинских документов в мобильном приложении. Библиотека должна включать:
1. Промпт для классификации документа — определяет тип (заключение, рецепт, анализы, направление, план лечения) и качество.
2. Промпт для извлечения сущностей — выделяет ФИО, даты, диагнозы, препараты, дозировки, врача, клинику.
3. Промпт для маскировки ПДн — заменяет персональные данные на маскированные значения.
4. Промпт для оценки уверенности — оценивает качество распознавания и формирует рекомендацию.
5. Промпт для суммаризации — создаёт краткое резюме документа для врача.

**Требования к библиотеке:**
1. Каждый промпт должен иметь версию, описание, примеры использования.
2. Должна быть документация по каждому промпту.
3. Промпты должны быть протестированы на 5+ примерах.
4. Реализована система версионирования (v1, v2, ...).

**Индикаторы:** LLM-5.1, LLM-5.4, LLM-5.6, LLM-5.8

**Пример реализации:**
```yaml
# prompts/classifiers/document_type_v1.3.yaml
id: classifier.document_type
version: 1.3.0
type: multimodal
model: gpt-4-vision
temperature: 0.1
max_tokens: 500
system_prompt: |
  Ты — эксперт по медицинской документации. 
  Анализируй изображение и определяй тип документа.
user_prompt: |
  Проанализируй изображение медицинского документа.
  Определи тип из списка:
  - conclusion (заключение врача)
  - recipe (рецепт)
  - analyses (результаты анализов)
  - referral (направление)
  - treatment_plan (план лечения)
  Оцени качество изображения (1-10).
  Верни JSON:
  {
    "document_type": "string",
    "confidence": 0.0-1.0,
    "quality_score": 1-10,
    "reasoning": "краткое обоснование"
  }
examples:
  - input: "image_recipe.jpg"
    output:
      document_type: "recipe"
      confidence: 0.92
      quality_score: 8
      reasoning: "Чёткое изображение рецепта с названиями препаратов"
tests:
  - case: "recipe_clear"
    expected_type: "recipe"
    min_confidence: 0.85
  - case: "conclusion_blurry"
    expected_type: "conclusion"
    min_confidence: 0.70
```

#### Задание 2. Реализация условного пайплайна для унификации расписания

**Источник кейса:** ООО «МедРокет» (Кейс «Унификация расписания приемов»)

**Постановка задачи:** Реализуйте условный пайплайн, который обрабатывает расписания из разных медицинских сервисов. Пайплайн должен:
1. Определять формат входных данных (JSON, XML, CSV, HTML).
2. Выбирать соответствующий промпт для парсинга.
3. Извлекать обязательные поля (дата, время, врач, статус слота).
4. Валидировать данные и обрабатывать ошибки.
5. Формировать единый формат на выходе.

**Условия выполнения:**
1. Предусмотрите обработку 3+ различных форматов.
2. Реализуйте fallback-промпт для неизвестных форматов.
3. Обеспечьте логирование всех этапов пайплайна.
4. Напишите минимум 3 теста для проверки работы пайплайна.

**Индикаторы:** LLM-5.2, LLM-5.4, LLM-5.5, LLM-5.6

**Пример реализации:**
```python
class SchedulePipeline:
    def __init__(self, feature_flags):
        self.feature_flags = feature_flags
        self.format_detectors = {
            "json": self._parse_json,
            "xml": self._parse_xml,
            "csv": self._parse_csv,
            "html": self._parse_html
        }
        self.fallback_detector = self._parse_fallback

    def process(self, raw_data):
        try:
            # Этап 1: Определение формата
            format_type = self._detect_format(raw_data)
            self.logger.info(f"Detected format: {format_type}")
            
            # Этап 2: Выбор парсера
            parser = self.format_detectors.get(
                format_type, 
                self.fallback_detector
            )
            
            # Этап 3: Парсинг
            parsed = parser(raw_data)
            
            # Этап 4: Валидация
            validated = self._validate(parsed)
            
            # Этап 5: Нормализация
            normalized = self._normalize(validated)
            return normalized
        except Exception as e:
            self.logger.error(f"Pipeline error: {e}")
            if self.feature_flags.get("enable_fallback"):
                return self._fallback_processing(raw_data)
            raise
```

#### Задание 3. Мультимодальный пайплайн для проверки достоверности отзывов

**Источник кейса:** ООО «МедРокет» (Кейс 5 «Проверка отзывов о врачах на накрутку»)

**Постановка задачи:** Разработайте мультимодальный пайплайн для проверки достоверности отзывов о врачах и клиниках. Пайплайн должен:
1. Принимать текст отзыва и (опционально) данные о пользователе и враче.
2. Выявлять признаки шаблонного или сгенерированного текста.
3. Сравнивать с уже опубликованными отзывами на наличие копипасты.
4. Формировать оценку риска (высокий/средний/низкий).
5. Принимать решение: опубликовать / отправить на модерацию / отклонить.

**Требования:**
1. Реализовать цепочку промптов с условной логикой.
2. Обеспечить передачу спорных случаев на ручную модерацию.
3. Логировать причины срабатывания каждого решения.
4. Протестировать на 10+ примерах.

**Индикаторы:** LLM-5.2, LLM-5.4, LLM-5.5, LLM-5.6, LLM-5.7

#### Задание 4. CI/CD для библиотеки промптов

**Постановка задачи:** Настройте CI/CD-пайплайн для автоматического тестирования и развертывания библиотеки промптов. Пайплайн должен включать:

**Автоматические проверки:**
1. Валидация синтаксиса промптов.
2. Тестирование на тестовых кейсах (не менее 10).
3. Проверка соответствия шаблонам.

**Канареечное развертывание:**
1. Развертывание новой версии на canary-окружение.
2. Автоматическое сравнение метрик качества (с A/B-тестированием).
3. Откат при падении метрик.

**Документация:**
1. Автоматическая генерация документации из метаданных.
2. Обновление README и примеров использования.

**Индикаторы:** LLM-5.2, LLM-5.6, LLM-5.8

**Пример структуры CI/CD:**
```
.gitlab-ci.yml
├── stages: [validate, test, canary, promote]
├── validate:
│   ├── syntax_check
│   └── schema_validation
├── test:
│   ├── unit_tests
│   ├── integration_tests
│   └── quality_metrics
├── canary:
│   ├── deploy_canary
│   ├── ab_testing (1 hour)
│   └── metrics_comparison
└── promote:
    ├── if metrics_ok → production
    └── if metrics_fail → rollback
```
