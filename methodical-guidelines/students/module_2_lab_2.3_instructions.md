# ⚙️ Пошаговая инструкция: Лабораторная работа 2.3 (Оптимизация RAG с автопроверкой)

**Цель:** Улучшить базовый RAG за счет гибридного поиска, реранкинга и переформулировки запросов, подтвердив улучшение метрик скриптом автопроверки.

## 📋 Этапы выполнения

### Шаг 1. Реализация BM25-ретривера
1. Установите библиотеку `rank_bm25`.
2. Реализуйте класс, который токенизирует ваш корпус (приведение к нижнему регистру, удаление пунктуации, лемматизация через `pymorphy2` или `nltk` для русского языка).
3. Проиндексируйте чанки из ЛР 2.2.

### Шаг 2. Гибридный поиск с RRF (Reciprocal Rank Fusion)
1. Реализуйте функцию, которая запрашивает `top-k*3` документов из Dense-поиска (FAISS/Qdrant) и `top-k*3` из BM25.
2. Объедините результаты по формуле RRF с константой `k_rrf = 60`:
   `RRF_score = 1 / (60 + rank_dense) + 1 / (60 + rank_bm25)`
3. Отсортируйте документы по убыванию RRF-скора.

### Шаг 3. Двухстадийный реранкинг (Cross-Encoder)
1. Используйте модель `cross-encoder/ms-marco-MiniLM-L-6-v2`.
2. Подавайте на вход реранкеру **только топ-20 или топ-50** кандидатов от гибридного поиска (чтобы не убить latency).
3. Отсортируйте кандидатов по новому скору и верните `top-5`.

### Шаг 4. Query Rewriting (Переформулировка запроса)
1. Реализуйте модуль, который перед поиском пропускает пользовательский запрос через LLM (или rule-based эвристику).
2. Промпт для LLM: *«Преобразуй этот вопрос в оптимальный поисковый запрос для векторной БД. Раскрой аббревиатуры, удали лишние местоимения. Выведи только запрос»*.
3. Установите `temperature = 0.1`.

### Шаг 5. Сборка пайплайна и запуск автопроверки
1. Интегрируйте все компоненты в класс `OptimizedRAGPipeline`.
2. Убедитесь, что в репозитории присутствует скрипт `evaluation/auto_check.py` и файл `evaluation/test_queries.json`.
3. Запустите скрипт: `python evaluation/auto_check.py`.

---

## ✅ Критерий успеха (PASS)
Скрипт выдаст `✅ АВТОПРОВЕРКА ПРОЙДЕНА`, если выполнено **хотя бы одно** условие:
1. Улучшение Recall@5 составляет **≥ 15%** относительно базовой линии (ЛР 2.2).
2. Абсолютное значение Recall@5 для оптимизированного пайплайна **≥ 0.85**.

## 💡 Советы и типичные ошибки
* ⚠️ **Ошибка:** RRF дает худший результат, чем чистый Dense. **Решение:** Проверьте токенизацию в BM25 (она должна корректно работать с русским языком) и убедитесь, что константа `k_rrf` равна 60.
* ⚠️ **Ошибка:** Cross-encoder работает слишком медленно. **Решение:** Уменьшите количество кандидатов, подаваемых на реранкинг (с 50 до 20).
* ⚠️ **Ошибка:** Нечестное сравнение. **Решение:** Используйте одну и ту же модель эмбеддингов (BGE-M3) и один и тот же тестовый датасет для Baseline и Optimized.
