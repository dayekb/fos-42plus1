## Занятие 1.1. Архитектура промпта и базовые паттерны

### Общие сведения

| Параметр | Значение |
|---|---|
| Форма проведения | Лекция с элементами интерактива |
| Продолжительность | 2 академических часа (90 минут) |
| Компетенция | LLM-5 |
| Индикаторы | 5.1, 5.2, 5.3 |
| Уровень освоения | Базовый |

### Цели занятия

1. Сформировать понимание промпт-инженерии как дисциплины.
2. Познакомить с архитектурой промпта: системный/пользовательский промпт, контекст, инструкция, примеры.
3. Объяснить принципы работы параметров генерации (`temperature`, `top-p`, `top-k`, `max_tokens`).
4. Дать представление о базовых паттернах: `zero-shot`, `few-shot`.
5. Познакомить с продвинутыми паттернами рассуждения: `Chain-of-Thought`, `Self-Consistency`.
6. Сформулировать критерии выбора техник под задачу.
7. Рассмотреть UX/UI аспекты проектирования интерфейсов для работы с промптами.

### Содержание лекции

#### 1. Введение: промпт-инженерия как дисциплина

**Промпт-инженерия** — дисциплина, изучающая методы проектирования, оптимизации и оценки входных запросов для LLM с целью получения целевого ответа.

**Архитектура промпта:**
- **Системный промпт** (`system prompt`) — задаёт роль модели, общие правила, стиль.
- **Пользовательский промпт** (`user prompt`) — содержит задачу, вопрос или инструкцию.
- **Контекст** — дополнительная информация для понимания задачи.
- **Инструкция** — чёткое описание требуемого действия.
- **Примеры** — демонстрация ожидаемого формата (`few-shot`).

#### 2. Настройка API и управление генерацией

| Параметр | Описание | Рекомендации |
|---|---|---|
| `temperature` | Контроль случайности/креативности. 0 — детерминированный вывод | Фактология: 0.0–0.3. Творчество: 0.7–1.0 |
| `top-p` | Ограничивает выбор токенов кумулятивной вероятностью p | 0.9–1.0 для большинства задач |
| `top-k` | Ограничивает выбор первыми K наиболее вероятными токенами | 20–50 для баланса |
| `max_tokens` | Ограничивает максимальную длину ответа | 50–100 (короткие), 500+ (развёрнутые) |

#### 3. Базовые паттерны промптов

- **Zero-shot** — выполнение задачи без примеров. Подходит для простых, хорошо знакомых модели задач.
- **Few-shot** — предоставление нескольких примеров перед запросом. Подходит для задач с нестандартным форматом.

**Структура качественного промпта:**
1. Роль (`system role`) — кто ты?
2. Инструкция / задача — что нужно сделать?
3. Контекст — какие данные нужны?
4. Ограничения — что нельзя делать?
5. Формат вывода — JSON, список, таблица и т.д.

#### 4. Продвинутые паттерны рассуждения

- **Chain-of-Thought (CoT)** — пошаговое рассуждение.
  - `Zero-shot CoT`: фраза «Давайте подумаем пошагово».
  - `Few-shot CoT`: примеры с пошаговыми рассуждениями.
- **Self-Consistency** — генерация множественных цепочек рассуждений через CoT, финальный ответ выбирается большинством голосов.

**Сравнение паттернов:**

| Паттерн | Когда использовать | Пример |
|---|---|---|
| Zero-shot | Простые задачи, стандартные форматы | Классификация, суммаризация |
| Few-shot | Формато-зависимые задачи | Извлечение структурированных данных |
| CoT | Сложные рассуждения | Математика, логика, multi-hop |
| Self-Consistency | Критичные задачи с высокой ответственностью | Медицинская диагностика, юриспруденция |

#### 5. UX/UI интерфейсы для работы с промптами

- Ввод: многострочное поле, шаблоны, история.
- Настройка параметров: визуальные контролы для `temperature`, `top-p`, `max_tokens`.
- Отображение: Markdown, JSON, потоковая генерация (streaming).
- Интеграция: управление контекстным окном, обработка ошибок, кэширование, логирование.
