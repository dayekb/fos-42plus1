### Цель лабораторной работы

Сформировать практические навыки:

1. Проектирования библиотеки промптов с единой структурой хранения и версионированием
2. Организации CI/CD пайплайна для автоматического тестирования, валидации и деплоя промптов
3. Применения методов отладки и контроля качества промптов (регрессионное тестирование, оценка стабильности)

---

### Описание кейса

Команда разрабатывает платформу для поиска и объединения IT-специалистов в проектные команды. Промпты, используемые для разных функций платформы (поиск подходящих кандидатов, рекомендация проектов, модерация описаний), разбросаны по коду, не имеют версионности, а любые правки приводят к неожиданным регрессиям в продакшене.

---

### Задание

Создать централизованную библиотеку промптов с системой версионирования и настроить CI/CD пайплайн, который автоматически проверяет качество промптов при каждом изменении.

---

### Последовательность действий

#### Часть А. Разработка библиотеки промптов (40% итоговой оценки)

- **Шаг 1.** Определить структуру библиотеки (директория `prompts/`, отдельные поддиректории для каждого сценария, YAML/JSON-файлы с обязательными полями: id, version, description, model, parameters, system, template, changelog)
- **Шаг 2.** Реализовать минимум три промпта: поиск кандидатов в команду, рекомендация проектов, модерация описания проекта
- **Шаг 3.** Реализовать загрузчик промптов на Python: функция `load_prompt(prompt_id, version=None)` с поддержкой версий и подстановкой переменных
- **Шаг 4.** Настроить управление версиями через Git с симлинком latest и ведением changelog

#### Часть Б. Настройка CI/CD пайплайна (30% итоговой оценки)

- **Шаг 5.** Подготовить тестовые наборы (≥5 примеров на промпт в директории `tests/fixtures/`)
- **Шаг 6.** Написать модульные тесты на Python (pytest) с инкрементальным тестированием
- **Шаг 7.** Настроить CI/CD пайплайн (GitHub Actions / GitLab CI): линтинг, запуск тестов, генерация отчёта, автоматический деплой в staging

#### Часть В. Документация и демонстрация (30% итоговой оценки)

- **Шаг 8.** Подготовить README.md с описанием структуры, команд, примеров использования
- **Шаг 9.** Подготовить демонстрацию работы системы
- **Шаг 10.** Сдать отчёт со структурой библиотеки, примерами промптов, описанием CI/CD, результатами тестирования

### Критерии оценивания

#### Часть А. Библиотека промптов (40 баллов)

| Критерий | 0–5 | 6–8 | 9–10 |
| --- | --- | --- | --- |
| Количество промптов | менее 3 | 3 | 3+ с разными типами задач |
| Структура хранения | нет единой структуры | базовая (YAML/JSON) | полная с метаданными, версией, параметрами |
| Шаблонизация и загрузчик | не реализованы | базовая подстановка | гибкая с валидацией переменных |
| Версионирование | отсутствует | ручное копирование | SemVer + changelog + симлинк latest |

#### Часть Б. CI/CD пайплайн (30 баллов)

| Критерий | 0–4 | 5–7 | 8–10 |
| --- | --- | --- | --- |
| Тестовые наборы | отсутствуют | есть, но <5 на промпт | ≥5 на каждый промпт, покрывают краевые случаи |
| Модульные тесты | не написаны | базовые (проверка формата) | полные с оценкой качества |
| Инкрементальное тестирование | не реализовано | частично | работает корректно |
| CI/CD пайплайн | не настроен | запускается вручную | полностью автоматический при PR/merge |

#### Часть В. Документация и демонстрация (30 баллов)

| Критерий | 0–5 | 6–8 | 9–10 |
| --- | --- | --- | --- |
| README.md | отсутствует или неполный | описание структуры и команд | полное с примерами и инструкциями |
| Демонстрация | не представлена | базовое видео/скриншоты | живая демонстрация или детальный отчёт с логами |
| Выводы и анализ | отсутствуют | поверхностные | глубокий анализ, предложения по улучшению |
