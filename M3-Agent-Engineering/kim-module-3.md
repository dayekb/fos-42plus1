# Контрольно-измерительные материалы (КИМ)
## Модуль 3: Инженерия агентов (Agent Engineering)

**Проверяемые компетенции:** LLM-4 (Проектирование и разработка автономных LLM-агентов),  BD (Работа с базами данных).  
**Общий балл за модуль:** 10 баллов (2 задания по 5 баллов).

---

### КИМ 3.1: "Вскрытие агента" (Agent Autopsy) 
**Формат:** Индивидуальное практическое задание (Code Debugging & Testing)  
**Максимальный балл:** 5 баллов  
**Время на выполнение:** 1 неделя  

**Легенда:**  
Вам передан репозиторий с "почти работающим" LLM-агентом для автоматического ресерча (использует фреймворк типа LangChain/LlamaIndex + Search API). Агент периодически попадает в бесконечный цикл рассуждений (ReAct loop) или некорректно парсит ответы внешних инструментов.

**Задача студента:**  
1. Локализовать ошибку в логике циклов или в промпте инструмента.  
2. Исправить код, добавив явное условие выхода (max iterations) и надежную обработку edge-кейсов (например, пустой ответ API).  
3. Написать 2 юнит-теста с использованием `pytest` и моков (`unittest.mock`) для критических путей агента.  

**Критерии оценивания (Рубрика):**  
| Критерий | Баллы | Описание |
| :--- | :---: | :--- |
| **Диагностика** | 1 | Ошибка точно найдена и кратко объяснена в комментарии/README. |
| **Исправление кода** | 2 | Код исправлен, агент успешно завершает задачу без зацикливания. |
| **Защита от сбоев** | 1 | Реализован механизм `max_iterations` и обработка ошибок API. |
| **Тестирование** | 1 | Написаны 2 работающих юнит-теста, покрывающих основной и граничный кейсы. |

### КИМ 3.2: "Оптимизация памяти и контекста" (Memory Leak Challenge)
**Формат:** Мини-проект / Лабораторная работа  
**Максимальный балл:** 5 баллов  
**Время на выполнение:** 2 недели  

**Легенда:**  
Чат-бот с долгосрочной памятью превышает лимит контекстного окна (или становится экономически неэффективным) после 10–15 сообщений из-за наивной конкатенации всей истории диалога в каждый новый промпт.

**Задача студента:**  
Реализовать и продемонстрировать один из механизмов управления памятью на выбор:  
- **Вариант А (Суммаризация):** Периодическая компрессия истории диалога через отдельный вызов легкой LLM.  
- **Вариант Б (Векторная память):** Сохранение истории в векторную БД и retrieval только релевантных прошлых сообщений (RAG для памяти).  

**Критерии оценивания (Рубрика):**  
| Критерий | Баллы | Описание |
| :--- | :---: | :--- |
| **Реализация** | 2 | Корректная программная реализация выбранного метода управления памятью. |
| **Эффективность** | 2 | Продемонстрировано снижение потребления токенов или времени отклика (скриншоты/логи до и после). |
| **Обоснование** | 1 | В README кратко обоснован выбор метода и его компромиссы (cost vs. accuracy). |
