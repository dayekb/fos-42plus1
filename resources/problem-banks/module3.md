## 🔍 Кейс 1. Агент мониторинга цен с уведомлениями

### 📋 Общая информация

| Параметр | Значение |
|----------|----------|
| **Источник** | Кейс «Разработка системы для мониторинга цен на товары» (Индустриальный партнер) |
| **Сложность** | ⭐⭐⭐ Средняя |
| **Ключевые паттерны** | ReAct, интеграция API, управление состоянием |

### 📝 Описание

Разработать LLM-агента для автоматического мониторинга цен на товары в интернет-магазинах. Агент должен собирать данные через API или веб-скрейпинг, анализировать динамику цен и уведомлять пользователей о снижении цен на отслеживаемые товары.

### 🔗 Связанные темы модуля 3

- ✅ **ReAct-паттерн** — планирование сбора данных → выполнение → анализ результатов
- 🔌 **Интеграция с внешними API** и веб-сервисами
- 💾 **Управление состоянием** — история цен, статус подписки
- 🛡️ **Обработка ошибок** и эскалация

### 🎯 Проверяемый результат

Работающий агент, который:
- ✅ Принимает от пользователя список товаров для отслеживания
- ✅ Периодически собирает актуальные цены из внешних источников
- ✅ Обнаруживает снижение цены и отправляет уведомление
- ✅ Ведёт историю изменения цен

### 📥 Входные данные

- Список URL или артикулов товаров
- Периодичность проверки (параметр)
- Порог снижения цены для уведомления

### ✅ Эталон / подход к проверке

- Агент корректно парсит цены с заданных источников
- Уведомления отправляются при достижении порога
- История цен сохраняется и доступна для просмотра
- Обработка ошибок (недоступность сайта, изменение структуры страницы)

### ⚙️ Варианты параметризации

- Количество отслеживаемых товаров (1–100)
- Тип источника (API / HTML-скрейпинг)
- Способ уведомления (Telegram, email, push)
- Использование кэширования для снижения нагрузки

## 🔍 Кейс 2. Агент-ассистент бронирования ресурсов

### 📋 Общая информация

| Параметр | Значение |
|----------|----------|

| **Ключевые паттерны** | Plan&Solve, интеграция календарей, управление памятью |

### 📝 Описание

Создать LLM-агента для управления бронированием общих ресурсов (переговорные комнаты, оборудование). Агент должен понимать запросы на естественном языке, проверять доступность, выполнять бронирование и предотвращать конфликты.

### 🔗 Связанные темы модуля 3

- 🧠 **Plan&Solve** — декомпозиция запроса: извлечение даты/времени → проверка доступности → бронирование
- 📅 **Интеграция с календарными сервисами** (Google Calendar, Outlook)
- 💾 **Управление памятью** — история бронирований, предпочтения пользователя
- 🛡️ **Обработка ошибок** и валидация

### 🎯 Проверяемый результат

Работающий агент-ассистент, который:
- ✅ Понимает запросы типа «Забронируй переговорную на завтра с 14:00 до 15:00»
- ✅ Проверяет доступность ресурсов в реальном времени
- ✅ Выполняет бронирование с валидацией конфликтов
- ✅ Отвечает на вопросы о расписании

### 📥 Входные данные

- Естественно-языковой запрос пользователя
- Каталог ресурсов с их характеристиками
- Текущее расписание бронирований

### ✅ Эталон / подход к проверке

- Корректное извлечение сущностей (дата, время, ресурс)
- Невозможность двойного бронирования одного слота
- Понятные ответы при ошибках (ресурс занят, время недоступно)
- Поддержка отмены и изменения бронирования

### ⚙️ Варианты параметризации

- Количество ресурсов (1–50)
- Поддержка разных типов ресурсов (комнаты, оборудование)
- Интеграция с внешними календарями
- Наличие ролевой модели (админ/пользователь)

## 🔍 Кейс 3. Агент обработки медицинских документов

### 📋 Общая информация

| Параметр | Значение |
|----------|----------|
| **Источник** | Кейс «Автоматическое распознавание и структурирование медицинских документов» (Индустриальный партнер) |
| **Сложность** | ⭐⭐⭐⭐ Высокая |
| **Ключевые паттерны** | Мультиагентность, OCR, управление памятью |

### 📝 Описание

Разработать агентный пайплайн для автоматической обработки медицинских документов (фото, PDF). Агент должен использовать OCR для распознавания текста, определять тип документа и извлекать структурированные данные (ФИО, диагнозы, препараты, даты).

### 🔗 Связанные темы модуля 3

- 🤖 **Мультиагентная оркестрация** — OCR-агент → классификатор → экстрактор сущностей
- 🔌 **Интеграция с внешними сервисами** (OCR API, LLM API)
- 💾 **Управление памятью** — сохранение результатов, история обработки
- 🎯 **Оценка уверенности** и эскалация к человеку

### 🎯 Проверяемый результат

Рабочий агентный пайплайн, который:
- ✅ Принимает изображение или PDF-файл
- ✅ Распознаёт текст с помощью OCR
- ✅ Определяет тип документа (заключение, рецепт, анализы)
- ✅ Извлекает ключевые сущности в структурированном виде
- ✅ Выдаёт предупреждение при низкой уверенности

### 📥 Входные данные

- Изображение или PDF медицинского документа
- (Опционально) метаданные о пациенте

### ✅ Эталон / подход к проверке

- Корректное распознавание текста на документах разного качества
- Правильное определение типа документа (≥80% accuracy)
- Извлечение всех ключевых сущностей
- Наличие механизма эскалации при низкой уверенности

### ⚙️ Варианты параметризации

- Тип документа (заключение, рецепт, анализы, направление)
- Язык документа (русский, английский)
- Качество изображения (высокое/низкое, перспективные искажения)
- Использование разных OCR-сервисов

## 🔍 Кейс 4. Агент безопасной передачи медицинских документов

### 📋 Общая информация

| Параметр | Значение |
|----------|----------|
| **Источник** | Кейс «Безопасная передача медицинских документов врачу через мобильное приложение» (Индустриальный партнер) |
| **Сложность** | ⭐⭐⭐ Средняя |
| **Ключевые паттерны** | ReAct, Guardrails, управление состоянием |

### 📝 Описание

Реализовать агента для безопасного предоставления доступа к медицинским документам. Агент управляет политиками доступа, временными ссылками, аудитом и возможностью отзыва прав.

### 🔗 Связанные темы модуля 3

- 🧠 **ReAct-паттерн** — анализ запроса → проверка прав → генерация ссылки → логирование
- 🔐 **Интеграция с системами аутентификации** и хранения документов
- 💾 **Управление состоянием** — активные доступы, история предоставлений
- 🛡️ **Безопасность и Guardrails** — проверка получателя, ограничение срока

### 🎯 Проверяемый результат

Работающий агент, который:
- ✅ Позволяет пользователю выбрать документы и указать получателя
- ✅ Генерирует защищённую ссылку с ограниченным сроком действия
- ✅ Отображает историю предоставлений
- ✅ Позволяет отозвать доступ в любой момент

### 📥 Входные данные

- Список документов для предоставления
- Идентификатор получателя (врач/клиника)
- Срок действия доступа (параметр)

### ✅ Эталон / подход к проверке

- Ссылка работает только для авторизованного получателя
- Доступ автоматически истекает по истечении срока
- Отзыв доступа работает мгновенно
- Все действия логируются с временем и участниками

### ⚙️ Варианты параметризации

- Срок действия (1 час, 24 часа, 7 дней, до отзыва)
- Тип получателя (конкретный врач, клиника, любой авторизованный)
- Поддержка множественных документов в одной ссылке
- Интеграция с внешними системами авторизации

### ⚙️ Варианты параметризации

- Количество поддерживаемых форматов (2–10)
- Тип источника (файл, API, база данных)

### 📋 Общая информация

| Параметр | Значение |
|----------|----------|
| **Источник** | Кейс «Проверка отзывов о врачах на накрутку и недостоверность» (Индустриальный партнер) |
| **Сложность** | ⭐⭐⭐⭐ Высокая |
| **Ключевые паттерны** | ReAct, векторная БД, пороги уверенности |

### 📝 Описание

Создать ИИ-агента для модерации отзывов о врачах. Агент должен анализировать текст отзыва на признаки копипасты, шаблонности, генерации ИИ и недостоверности, а также принимать решение о публикации.

### 🔗 Связанные темы модуля 3

- 🧠 **ReAct-паттерн** — анализ текста → проверка по базе → оценка риска → решение
- 🔌 **Интеграция с векторной БД** (поиск похожих отзывов)
- 💾 **Управление памятью** — история решений модератора
- 🎯 **Пороги уверенности** и эскалация к человеку

### 🎯 Проверяемый результат

Работающий агент модерации, который:
- ✅ Принимает текст отзыва и (опционально) данные о пользователе
- ✅ Проверяет наличие похожих отзывов в базе
- ✅ Оценивает риск недостоверности
- ✅ Выдаёт рекомендацию: опубликовать, отправить на модерацию, отклонить

### 📥 Входные данные

- Текст отзыва
- (Опционально) ID пользователя, ID врача, факт приёма

### ✅ Эталон / подход к проверке

- Обнаружение копипасты даже при небольших изменениях
- Выявление шаблонных и сгенерированных текстов
- Настраиваемые пороги риска
- Спорные случаи направляются на ручную модерацию

### ⚙️ Варианты параметризации

- Порог срабатывания (низкий/средний/высокий)
- Использование факта приёма для проверки
- Поддержка разных языков
- Интеграция с внешними API для проверки
