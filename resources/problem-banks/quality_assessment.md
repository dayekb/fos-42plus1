# Банк задач «Оценка качества (LLM‑as‑a‑judge)»

**Аннотация:** Комплексные задачи на разработку judge-промптов для сравнения версий (A/B), обнаружения галлюцинаций, валидации JSON-схем и оценки безопасности. Задания ориентированы на интеграцию в CI/CD пайплайны и подготовку к защите проектов.

---

## Задача №1. Сравнение двух версий (A/B-компаратор)

**Условие:**  
Напишите judge-промпт для сравнения двух версий (A и B) одного и того же промпта. Оцените по критериям: точность, полнота, структурированность, ясность, релевантность. Верните JSON с оценками и рекомендацией.

**Проверяемый результат:**  
- Judge-промпт использует роль эксперта  
- Все пять критериев оценены по шкале 1–10  
- Выбран победитель с обоснованием  
- Рекомендация соответствует разнице в баллах  

**Сложность:** ★★ (средняя)  

**Входные данные:**  
Два ответа на один запрос (классификация текста). Ground truth прилагается.

**Эталон / подход к проверке:**  
Проверяется, что judge выставил более высокий балл версии, которая ближе к ground truth. Коэффициент корреляции между оценкой judge и эталоном должен быть ≥ 0.8.

**Варианты параметризации:**  
- Добавить больше критериев (безопасность, отсутствие галлюцинаций)  
- Изменить задачу (извлечение vs классификация)  
- Добавить few-shot примеры в judge-промпт

## Задача №2. Обнаружение галлюцинаций

**Условие:**  
Разработайте judge-промпт, который анализирует ответ модели и выявляет галлюцинации (утверждения, отсутствующие в контексте или противоречащие ему). Классифицируйте галлюцинации по типам (фактические, логические, противоречия).

**Проверяемый результат:**  
- Все галлюцинации обнаружены  
- Тип каждой галлюцинации определён корректно  
- Рассчитана доля галлюцинаций  
- Дана оценка серьёзности  

**Сложность:** ★★★ (продвинутая)  

**Входные данные:**  
Контекст (статья) и ответ модели, содержащий выдуманные факты.

**Эталон / подход к проверке:**  
Сравнение с разметкой эксперта. Точность обнаружения галлюцинаций (precision/recall) ≥ 0.9.

**Варианты параметризации:**  
- Изменить тип контекста (новости, наука)  
- Добавить полуправдивые утверждения  
- Усложнить логику (противоречия внутри ответа)

---

## Задача №3. Валидация JSON-схемы

**Условие:**  
Напишите judge-промпт, который проверяет, соответствует ли выданный моделью JSON заданной схеме (типы, обязательные поля). Если не соответствует — перечислить ошибки.

**Проверяемый результат:**  
- Валидность JSON подтверждена или опровергнута  
- Все ошибки валидации перечислены  
- Выставлена оценка соответствия схеме (0-10)  

**Сложность:** ★★ (средняя)  

**Входные данные:**  
JSON-схема и ответ модели.

**Эталон / подход к проверке:**  
Сравнение с автоматической валидацией (например, через Python `jsonschema`). Совпадение ошибок ≥ 90%.

**Варианты параметризации:**  
- Изменить схему (добавить вложенные объекты)  
- Внести невалидные данные (неправильный тип, пропущенные поля)  
- Добавить несколько схем

## Задача №4. Оценка безопасности через judge

**Условие:**  
Спроектируйте judge-промпт, который тестирует промпт на устойчивость к атакам (инъекции, джейлбрейк). Judge должен проанализировать ответы на набор вредоносных запросов и выдать оценку безопасности по пяти критериям.

**Проверяемый результат:**  
- Все векторы атак протестированы  
- Выставлены оценки по каждому критерию  
- Итоговая оценка безопасности  
- Перечень уязвимостей  

**Сложность:** ★★★ (продвинутая)  

**Входные данные:**  
Тестируемый промпт и набор из 5 атак.

**Эталон / подход к проверке:**  
Сравнение с экспертной оценкой. Коэффициент корреляции ≥ 0.8.

**Варианты параметризации:**  
- Изменить набор атак  
- Добавить специфические для домена атаки  
- Оценить разные модели

## Задача №5. Комплексный judge для CI/CD

**Условие:**  
Разработайте judge-промпт, который автоматически принимает решение о продвижении новой версии промпта в production на основе сравнения A/B, анализа галлюцинаций и валидации JSON. Промпт должен вернуть JSON с итоговой рекомендацией и пояснением.

**Проверяемый результат:**  
- Учтены все три аспекта (качество, галлюцинации, валидация)  
- Рекомендация обоснована  
- Возвращён JSON со всеми метриками  

**Сложность:** ★★★ (продвинутая)  

**Входные данные:**  
Результаты A/B-теста, отчёт о галлюцинациях, результат JSON-валидации.

**Эталон / подход к проверке:**  
Проверяется, что рекомендация соответствует заданным правилам (например, если качество B выше на 0.5 балла и галлюцинаций меньше — promote B).

- Изменить пороговые значения
