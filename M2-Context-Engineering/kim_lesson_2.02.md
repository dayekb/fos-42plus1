## 10. Варианты заданий к лабораторной работе

## Реализация пайплайна извлечение→чтение

**Дисциплина:** Инженерия систем на базе больших языковых моделей  
**Модуль:** 2. Context Engineering (Расширение контекста и RAG)  
**Тип заданий:** Индивидуальные варианты для лабораторной работы

---

## Общая структура выполнения (для всех вариантов)

Каждый вариант включает обязательные этапы:

1. Загрузка и предобработка документов.
2. Чанкинг с заданными параметрами.
3. Вычисление эмбеддингов.
4. Индексация в векторной БД.
5. Реализация поиска и формирования контекста.
6. Генерация ответа с цитированием.
7. Оценка качества ретривала (Recall@k).
8. Оформление отчёта.

---

## Вариант 1. Корпоративный FAQ-бот

| Параметр | Значение |
|----------|----------|
| **Датасет** | Внутренний FAQ компании (10–15 документов, формат .txt) |
| **Модель эмбеддингов** | BGE-M3 (sentence-transformers) |
| **Векторная БД** | FAISS |
| **Чанкинг** | Фиксированный размер: 512 токенов, перекрытие 50 токенов |
| **LLM для генерации** | GPT-4o-mini (OpenAI API) |
| **Доп. требование** | Ответы должны ссылаться на конкретный документ из FAQ |

**Ожидаемый результат:** Работающий RAG-пайплайн для ответов на вопросы по внутренней документации компании с цитированием источников.

---

## Вариант 2. Техническая документация Python

| Параметр | Значение |
|----------|----------|
| **Датасет** | Официальная документация Python (5–10 страниц, формат .txt/.md) |
| **Модель эмбеддингов** | OpenAI `text-embedding-3-small` |
| **Векторная БД** | Qdrant (локальный Docker) |
| **Чанкинг** | Sliding Window: 256 токенов, перекрытие 30 токенов |
| **LLM для генерации** | Mistral 7B (локально через Ollama) |
| **Доп. требование** | Реализовать фильтрацию по метаданным (версия Python, модуль) |

**Ожидаемый результат:** RAG-система для поиска информации по документации Python с возможностью фильтрации по версии.
