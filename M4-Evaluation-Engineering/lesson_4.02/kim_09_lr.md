## 🧪 КИМ №9.1. Лабораторная работа «Автоматическая оценка качества генерации» (средний уровень)

### Паспорт оценочного средства

| Параметр | Значение |
|----------|----------|
| **Наименование** | Оценка качества генеративных моделей с использованием метрик и LLM‑as‑a‑Judge |
| **Вид КИМ** | Лабораторная работа с отчётом |
| **Компетенции** | LLM‑1.2 (средний), LLM‑1.7 (средний), PL‑1.2 (средний) |
| **Уровень освоения** | Средний |
| **Время выполнения** | 2–3 часа (аудиторная + самостоятельная работа) |

### Задание

На основе предоставленного датасета (пары «запрос – эталонный ответ») и открытой LLM (например, GPT‑4 API, YandexGPT или локальная LLaMA):

1. **Сгенерируйте ответы модели** на 50–100 запросов.
2. **Для каждого ответа вычислите автоматические метрики:**
   - BLEU, ROUGE‑L, METEOR, BERTScore (с помощью `evaluate` или `torchmetrics`).
3. **Организуйте оценку с помощью LLM‑as‑a‑Judge:**
   - Разработайте промпт для судьи (критерии: точность, полнота, релевантность, стиль).
   - Получите оценку от LLM-судьи по 5‑балльной шкале.
4. **Проведите корреляционный анализ** (Spearman) между автоматическими метриками и оценкой судьи.
5. **Сравните время выполнения и стоимость** (если применимо) для каждого подхода.
6. **Сделайте вывод** о применимости метрик в вашем сценарии.

### Критерии оценки

- Корректность реализации скрипта на Python (использование библиотек, обработка данных).
- Глубина анализа (интерпретация корреляций, обсуждение ограничений метрик).
- Качество отчёта (структурированность, выводы, визуализации).

## 🧪 КИМ №9.2. Лабораторная работа «Анализ безопасности и устойчивости LLM» (средний уровень)

### Паспорт оценочного средства

| Параметр | Значение |
|----------|----------|
| **Наименование** | Тестирование устойчивости LLM к состязательным атакам и фильтрация контента |
| **Вид КИМ** | Лабораторная работа с отчётом |
| **Компетенции** | LLM‑1.5 (средний), AI S‑2.1 (средний) |
| **Уровень освоения** | Средний |
| **Время выполнения** | 2–3 часа |

### Задание

Используя открытую LLM и библиотеку `TextAttack` или `PromptInject`:

1. **Разработайте набор состязательных промптов:**
   - Инъекция (переопределение системной инструкции).
   - «Джейлбрейк» (получение запрещённого контента).
   - Атака на основе перефразирования (семантически эквивалентные, но с изменённым синтаксисом).
2. **Проведите тестирование модели на этих промптах:**
   - Зафиксируйте успешность атаки (доля ответов, нарушающих политику).
   - Измерьте изменение перплексии и токсичности ответов.
3. **Реализуйте простую защиту:**
   - Фильтр входных промптов (регулярные выражения, детектор инъекций на основе классификатора).
   - Постобработка ответа (замена нецензурной лексики, отклонение подозрительных запросов).
4. **Повторите тесты с защитой** и сравните показатели (успешность атак, качество ответов на легитимные запросы).
5. **Оцените влияние защиты** на задержку и вычислительные затраты.

### Критерии оценки

- Полнота выявленных векторов атак.
- Обоснованность выбора методов защиты.
- Количественное сравнение «до/после» с метриками (ASR, точность, F1).
- Анализ компромиссов (безопасность vs. полезность).
