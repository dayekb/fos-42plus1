## 🔹 СР №1. Идентификация угроз и уязвимостей LLM-систем (КИМ №14)

**Цель:** Научиться систематически выявлять угрозы, классифицировать атаки и применять методики моделирования угроз (MITRE ATLAS, STRIDE) для LLM-решений.

### Задание

Вам предложен гипотетический LLM-сервис: **чат-бот для онлайн-банка**, который:
- принимает текстовые запросы пользователей;
- обращается к внутренней базе знаний (RAG);
- выдаёт ответы, содержащие персональные данные клиента (номер счета, баланс, ФИО);
- использует проприетарное API (GPT-4) и хранит историю диалогов.

1. **Составьте список активов** системы (данные, модели, API-ключи, логи, инфраструктура).
2. **Постройте модель угроз**, используя **MITRE ATLAS** (выберите минимум 5 техник атак, актуальных для этой системы) и опишите для каждой:
   - цель атакующего;
   - вектор атаки (данные, модель, API, MLOps);
   - потенциальный ущерб (конфиденциальность, целостность, доступность).
3. **Примените методику STRIDE** к основным компонентам (модель, хранилище данных, API-шлюз, пайплайн обучения) и определите минимум **3 уязвимости** (например, подделка авторизации, раскрытие информации, отказ в обслуживании).
4. Для каждой выявленной уязвимости предложите **меру защиты** (техническую или организационную).
5. **Приоритизируйте риски** по матрице «Вероятность × Влияние» и составьте **план реагирования** (минимум 3 сценария).

### Индикаторы выполнения

| № | Индикатор | Описание |
|---|-----------|----------|
| 1.1 | Инвентаризация активов | Составлен список всех компонентов системы с указанием критичности. |
| 1.2 | Применение MITRE ATLAS | Выбрано ≥5 техник атак с описанием вектора и ущерба. |
| 1.3 | STRIDE-анализ | Проведён анализ для 3 компонентов, выделены конкретные уязвимости. |
| 1.4 | Меры защиты | Для каждой уязвимости предложена обоснованная контрмера (например, входная фильтрация, аудит логов, шифрование). |
| 1.5 | Матрица рисков | Риски ранжированы, определены приоритеты и план действий. |

### Формат сдачи
- Отчёт (PDF) с таблицами, диаграммами (диаграмма потоков данных, матрица рисков).

## 🔹 СР №2. Разработка и тестирование Guardrails (КИМ №15)

**Цель:** Спроектировать и реализовать защитные механизмы (guardrails) для LLM-системы, обеспечивающие фильтрацию входов и выходов, а также противодействие промпт-инъекциям.

### Задание

На основе сервиса из СР №1 разработайте **модуль Guardrails**, который включает:

1. **Входной фильтр**:
   - регулярное выражение для выявления PII (паспортные данные, email, телефон);
   - детектор промпт-инъекций (на основе списка ключевых фраз, например, *«ignore previous instructions»*, *«system prompt»*);
   - дополнительно – классификатор на основе ML (например, fine-tuned BERT) для определения вредоносных запросов.

2. **Выходной фильтр**:
   - проверка на наличие PII (пост-обработка: маскирование или отклонение ответа);
   - детекция токсичности (использовать готовую модель, например, `unbiased-toxic-bert` или `Detoxify`);
   - контроль длины и формата (ответ не должен превышать 2000 символов).

3. **Тестирование защит**:
   - подготовьте набор тестовых промптов (20 штук), включая:
     - 5 легитимных запросов;
     - 5 инъекционных (с переопределением инструкций);
     - 5 с PII;
     - 5 с токсичным контентом.
   - запустите систему с включёнными guardrails и без них, зафиксируйте:
     - долю заблокированных запросов;
     - задержку на каждый фильтр;
     - ложноположительные срабатывания (легитимные запросы ошибочно заблокированы).

4. **Напишите отчёт** с анализом компромиссов:
   - как защита влияет на user experience (задержка, блокировки);
   - как минимизировать ложные срабатывания;
   - какие улучшения можно предложить.

### Индикаторы выполнения

| № | Индикатор | Описание |
|---|-----------|----------|
| 2.1 | Реализация фильтров | Код на Python содержит входной и выходной фильтры с использованием регулярных выражений и/или моделей. |
| 2.2 | Тестовый набор | Сформирован репрезентативный набор из 20 промптов с разметкой категорий. |
| 2.3 | Замеры эффективности | Приведена таблица с результатами: обнаруженные угрозы, ложные срабатывания, пропущенные угрозы. |
| 2.4 | Оценка производительности | Измерена задержка каждого фильтра (в мс) и общая задержка в сравнении с базой. |
| 2.5 | Анализ компромиссов | Сделан вывод о применимости фильтров в продуктивной среде, даны рекомендации по настройке порогов. |

### Формат сдачи
- Jupyter Notebook с кодом и тестами.
- Краткий отчёт (1–2 стр.) с таблицами и выводами.

## 🔹 СР №3. Логирование, наблюдаемость и детекция аномалий (КИМ №16)

**Цель:** Настроить систему сбора логов, анализировать поведение LLM-сервиса и выявлять аномалии (включая атаки и сбои).

### Задание

Вам дан **синтетический дамп логов** (CSV с колонками: `timestamp`, `request_id`, `user_id`, `prompt`, `response`, `tokens_in`, `tokens_out`, `latency_ms`, `status_code`, `guardrail_triggered`). Логи содержат 10 000 записей за 7 дней, включая нормальные запросы, инъекции, ошибки и скачки задержки.

1. **Разработайте пайплайн обработки логов** на Python:
   - загрузка и очистка данных;
   - расчёт агрегированных метрик (суточные средние, перцентили latency, частота ошибок, доля срабатываний guardrail);
   - построение временных рядов для ключевых KPI.

2. **Внедрите детекцию аномалий**:
   - **статистический метод** – межквартильный размах (IQR) или правило 3-сигма для latency и token_usage;
   - **метод скользящего окна** – вычисление скользящего среднего и стандартного отклонения, сигнал при превышении порога (например, 2σ);
   - **обнаружение дрейфа распределения** промптов/ответов с помощью PSI между днями.

3. **Смоделируйте инцидент**:
   - найдите в логах конкретную аномалию (например, внезапный рост latency или всплеск инъекционных запросов).
   - опишите, как бы вы настроили алерт, чтобы он сработал до того, как проблема затронет пользователей.

4. **Спроектируйте дашборд** (статический, с использованием `matplotlib`/`plotly`) для визуализации:
   - latency (p95, p99) по часам;
   - частота ошибок (5xx);
   - доля заблокированных guardrail-запросов;
   - топ-10 самых длинных промптов (подозрение на атаку).

5. **Напишите сценарий реагирования**:
   - что делать при срабатывании алерта (автоматические действия, эскалация).

### Индикаторы выполнения

| № | Индикатор | Описание |
|---|-----------|----------|
| 3.1 | ETL-пайплайн | Реализован скрипт для загрузки, фильтрации и агрегации логов. |
| 3.2 | Детекция аномалий | Применены ≥2 метода (IQR/3σ, скользящее окно, PSI) и выявлены точки аномалий. |
| 3.3 | Анализ инцидента | Найден и описан конкретный случай (например, атака или сбой). |
| 3.4 | Визуализация | Построены графики с аннотациями аномалий, дашборд содержит все обязательные метрики. |
| 3.5 | План реагирования | Подготовлен чёткий алгоритм действий (автоматический банинг запросов, откат модели, уведомление команды). |

### Формат сдачи
- Архив с кодом и сгенерированными графиками (HTML или PDF).
- Отчёт с описанием инцидента и планом реагирования.

## 🔹 СР №4. Оценка рисков и соответствие регуляторным требованиям (КИМ №17)

**Цель:** Научиться проводить оценку воздействия на защиту данных (DPIA), анализировать соответствие этическим и правовым нормам, а также формировать политику ответственного использования ИИ.

### Задание

В продолжение сервиса из СР №1 (чат-бот банка) необходимо подготовить **пакет документов** для внутреннего комитета по этике и регулятора (Роскомнадзор).

1. **Проведите оценку воздействия на защиту персональных данных (DPIA)**:
   - опишите, какие категории персональных данных обрабатываются;
   - оцените риски для субъектов (например, утечка, неправомерный доступ);
   - предложите меры по снижению рисков (технические: шифрование, анонимизация; организационные: политика доступа, обучение персонала).

2. **Проверьте соответствие требованиям**:
   - **152-ФЗ** (закон о персональных данных): какие обязанности возникают у оператора?
   - **GDPR** (если применимо): какие права субъектов и как они реализуются?
   - **Кодекс этики в сфере ИИ РФ**: какие принципы нарушаются потенциально и как их соблюсти?

3. **Разработайте политику «Ответственного и безопасного ИИ»** для организации, включающую:
   - принципы прозрачности, подотчётности, справедливости;
   - процедуры аудита и контроля за LLM-системой;
   - план действий при выявлении предвзятости или дискриминации.

4. **Подготовьте краткую памятку для пользователей** о том, как их данные используются в системе, и какие у них есть права.

5. **Оцените операционные риски** (юридические, репутационные, финансовые) и предложите **стратегию страхования** или резервирования средств на покрытие возможных штрафов.

### Индикаторы выполнения

| № | Индикатор | Описание |
|---|-----------|----------|
| 4.1 | DPIA | Оформлен документ с описанием данных, рисков и мер. |
| 4.2 | Анализ соответствия | Проведена сверка с 152-ФЗ, GDPR и этическим кодексом, указаны несоответствия (если есть) и планы по их устранению. |
| 4.3 | Политика ИИ | Разработан документ на 2–3 страницы, охватывающий все этапы жизненного цикла системы. |
| 4.4 | Памятка пользователям | Чёткое, доступное описание обработки данных и прав пользователей. |
| 4.5 | Финансовые оценки | Приведена оценка потенциальных штрафов и затрат на страхование, дана рекомендация по резервированию. |

### Формат сдачи
- Пакет документов (PDF/Word):
  - DPIA;
  - Политика ответственного ИИ;
  - Памятка пользователям;
  - Финансово-рисковый анализ.
