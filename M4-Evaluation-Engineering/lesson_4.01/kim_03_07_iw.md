# 📌 ЗАНЯТИЕ 4.1. Выбор модели и развертывание LLM-сервисов

## КИМ №3–7 (ОС №3–7). Задания для самостоятельной работы

### Цель
Углубить прикладные навыки Python для LLM-сервисов. Каждое задание требует рабочего кода и краткого описания найденных/исправленных ошибок.

### Список заданий

**СР №1. Асинхронный клиент с устойчивостью к сбоям**
Реализуйте LLM-клиент на `httpx.AsyncClient` с таймаутом, до 3 ретраев на 429/5xx и circuit breaker после N подряд ошибок. Покройте тестами сценарии успеха, ретрая и открытия circuit.

**СР №2. Конфигурация окружений**
Вынесите параметры модели в `pydantic-settings`. Покажите переключение `MODEL_NAME` без изменения кода (dev / staging / prod). Добавьте валидацию: при пустом `API_KEY` для облачного режима сервис не стартует.

**СР №3. Health / readiness и graceful shutdown**
Разделите `/health` (liveness) и `/ready` (проверка доступности LLM). При SIGTERM дождитесь завершения текущих запросов (или корректно отмените их) и закройте HTTP-клиент.

**СР №4. Streaming (SSE)**
Добавьте эндпоинт `/v1/chat/stream`, который проксирует token stream от LLM. Клиентский пример (curl или маленький Python-скрипт) приложите к README.

**СР №5. Отладка типовых дефектов**
Найдите и исправите 3 «сломанных» фрагмента кода (выдаются преподавателем или из чек-листа), приложив дифф и новые тесты. Минимум один дефект должен быть связан с конкурентностью или жизненным циклом ресурсов.
